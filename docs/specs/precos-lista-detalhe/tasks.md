- Visual: conferido no Chrome com dados de exemplo (desktop: lista, detalhe, placa, simulador; "celular": lista sozinha e detalhe sozinho com **← Preços**). O headless do Chrome não renderiza abaixo de ~500 px, então a largura real de telefone (abaixo de 480 px, onde o cabeçalho empilha e o simulador empilha os controles) não foi vista em tela.
- Desvios do techspec: `salvo=criado` e a seleção padrão ficaram em `useSelecaoPrecos` (a seleção precisa dos dados da lista, que `usePrecosUrlState` não tem); o foco entre itens é feito por `PrecoListItem` (`onMoverFoco`) e pelo contêiner (roving tabindex); a página de carga usa `Promise.all` nas páginas 2 em diante (a ordem da API é mantida); o botão **Voltar** do detalhe é um botão de texto "← Preços" que só aparece abaixo de `md` (o cabeçalho fixo no celular depende do contêiner rolar, não foi necessário `position: sticky`).
- Os testes de `PrecosMasterDetail` forçam o layout de desktop com uma regra de CSS no teste, porque o jsdom não aplica media query (sem isso o detalhe ou a lista ficariam escondidos); os de celular usam as regras reais.
- Corrigido junto: `beforeEach(() => vi.mocked(x).mockReset())` devolve o mock e o vitest o chama como limpeza, o que causava uma falha intermitente em `useMeiosPagamento.test.tsx`; agora o `beforeEach` não devolve nada.
- Pontos a confirmar com o back continuam em aberto (techspec): tamanho máximo de página de `GET /rotatividade` (hoje 50 em `TAMANHO_PAGINA_CARGA`), regras reais da estimativa, se os ids crescem com o tempo e que horário nulo significa dia inteiro.
